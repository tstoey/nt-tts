# Requirement checklist (password-locked)

หน้าเช็กลิสต์คำถามเก็บ requirement สำหรับใช้ในการประชุม เปิดบน GitHub Pages และล็อกด้วยรหัสผ่าน

**ความปลอดภัย**
- เนื้อหาทั้งหน้าเข้ารหัสด้วย AES-256-GCM (กุญแจ derive จากรหัสผ่านด้วย PBKDF2-SHA256 600,000 รอบ)
- ใน repo มีเฉพาะไฟล์ที่เข้ารหัสแล้ว
- คำตอบที่จดไว้ไม่ได้ขึ้น GitHub

**คำตอบเก็บที่ไหน (เลือกตอน build)**
- **มี `src/firebase.config.json`:** เก็บใน Firestore ของ Firebase ทีมล็อกอินด้วย Google แล้วเห็นข้อมูลชุดเดียวกันทันที (ดูหัวข้อ “ตั้งค่า Firebase”)
- **ไม่มี:** เก็บในเบราว์เซอร์ของแต่ละคน แล้วรวมกันด้วยการส่งออก / นำเข้าไฟล์

## โครงสร้างโฟลเดอร์

| path | คืออะไร | ขึ้น GitHub? |
|---|---|---|
| `src/index.src.html` | หน้าฉบับทีม อ่านได้ มีโน้ตที่ใช้ภายในทีม | **ไม่** (อยู่ใน .gitignore) |
| `src/firebase.config.json` | ค่าเชื่อมต่อ Firebase ของโปรเจกต์ (คัดลอกจาก `firebase.config.example.json`) | **ไม่** (อยู่ใน .gitignore) |
| `src/firestore.rules` | กฎสิทธิ์ของ Firestore และรายชื่ออีเมลทีม นำไปวางใน Firebase Console | **ไม่** (อยู่ใน .gitignore) |
| `exports/` | ไฟล์คำตอบที่ส่งออก มีข้อมูลลูกค้า | **ไม่** (อยู่ใน .gitignore) |
| `scripts/build.mjs` | ตัด team notes ออก เข้ารหัส แล้วเขียน `docs/` | ได้ |
| `docs/index.html` | หน้าที่เข้ารหัสแล้ว เป็นไฟล์ที่ GitHub Pages เสิร์ฟ | ได้ |

## ขึ้น GitHub Pages ครั้งแรก

ต้องมี Node 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

1. **Build:** ระบบจะถามรหัสผ่านสองครั้ง ต้องยาวอย่างน้อย 12 ตัวอักษร ใช้วลียาวๆ ที่เดายาก
   ```bash
   node scripts/build.mjs
   ```
2. **สร้าง git repo แล้วตรวจไฟล์:**
   ```bash
   git init -b main
   git add .
   git status
   ```
   ต้องเห็นแค่ `.gitignore`, `README.md`, `scripts/` และ `docs/` ถ้ามี `src/` หรือ `exports/` **ห้าม commit**
3. **Commit และ push:**
   ```bash
   git commit -m "Publish requirement checklist"
   ```
   push ขึ้น repo บน GitHub ได้ทั้ง public และ private แต่ GitHub Pages จะเปิดให้ทุกคนเห็นเสมอ ควรตั้งชื่อ repo เป็นกลาง ไม่ใส่ชื่อลูกค้า
4. **เปิด Pages:** บน GitHub ไปที่ Settings → Pages → Build and deployment → Source: **Deploy from a branch** แล้วเลือก Branch: `main`, Folder: `/docs` → Save
5. **ส่งให้ทีม:** ส่งลิงก์และรหัสผ่านให้ทีม**แยกช่องทางกัน** เช่น ลิงก์ทางอีเมล รหัสทางแชท

## ตั้งค่า Firebase (ฐานข้อมูลของทีม)

ทำใน [Firebase Console](https://console.firebase.google.com) ครั้งเดียว

1. **สร้างโปรเจกต์:** Add project ปิด Google Analytics ได้
2. **เปิด Firestore:** Build → Firestore Database → Create database
   - เลือก **Production mode**
   - เลือก location ใกล้ไทย เช่น `asia-southeast1` (สิงคโปร์) **เปลี่ยนภายหลังไม่ได้**
3. **เปิดล็อกอินด้วย Google:**
   - Build → Authentication → Get started → Sign-in method → **Google** → Enable
   - แท็บ Settings → Authorized domains → เพิ่ม `tstoey.github.io` (โดเมนของ GitHub Pages)
4. **สร้าง Web app:**
   - Project settings (รูปเฟือง) → Your apps → ไอคอน `</>` → ตั้งชื่อแอป ไม่ต้องเปิด Hosting
   - คัดลอกค่า `firebaseConfig` มาวางใน `src/firebase.config.json` ตามรูปแบบของ `src/firebase.config.example.json`
   - ค่านี้ไม่ใช่ความลับ สิ่งที่กันคนนอกคือกฎในข้อ 5
5. **ตั้งสิทธิ์:**
   - แก้รายชื่ออีเมลใน `src/firestore.rules` ให้เป็นอีเมล Google ของคนในทีม (ตัวพิมพ์เล็ก)
   - คัดลอกทั้งไฟล์ไปวางที่ Firestore Database → Rules → **Publish**
   - เพิ่มหรือลบคนภายหลัง: แก้ไฟล์นี้แล้ว Publish ใหม่ ไม่ต้อง build หน้าใหม่
6. **Build แล้ว push** ตามหัวข้อ “แก้เนื้อหาภายหลัง” ตอน build จะเห็นบรรทัด “ฐานข้อมูลของทีม: Firebase โปรเจกต์ …”
7. **ย้ายคำตอบเดิมขึ้นฐานข้อมูล:** ล็อกอินแล้วกด **นำเข้าไฟล์** เลือก `exports/claude-ai-20261118.json` และไฟล์ที่ทีมส่งออกไว้
   - หน้าจะถามยืนยันก่อน เพราะทุกคนเห็นทันทีและย้อนกลับไม่ได้

**ใช้งานกับ Firebase**
- **คนในรายชื่อ:** ใส่รหัสหน้าเว็บ แล้วกด **ล็อกอินด้วย Google** ทุกคนเห็นคำตอบชุดเดียวกันทันที ชื่อที่แสดงข้างคำตอบมาจากบัญชี Google
- **คนที่ไม่อยู่ในรายชื่อ:** เห็นคำถาม แต่ไม่เห็นและแก้คำตอบไม่ได้
- **สำรองข้อมูล:** **ส่งออกไฟล์** ยังใช้ได้ ควรส่งออกเก็บไว้เป็นระยะ
- **โควตาแผนฟรี (Spark):** พอสำหรับทีมเล็ก ถ้าเกินโควตาของวัน จะบันทึกไม่ได้จนถึงวันถัดไป

## แก้เนื้อหาภายหลัง

1. แก้ `src/index.src.html` เปิดดูในเบราว์เซอร์ตรงๆ ได้ (จะเข้าโหมดบันทึกในเครื่อง)
2. Build ใหม่ด้วย `node scripts/build.mjs`
   - ใช้รหัสเดิม: คนที่ติ๊ก “จำไว้ในเครื่องนี้” จะเปิดได้ทันทีเหมือนเดิม
   - เปลี่ยนรหัส: ทุกคนต้องใส่รหัสใหม่
3. Commit และ push `docs/index.html`

คำตอบที่ทุกคนจดไว้ไม่หาย เพราะรหัสข้อไม่เปลี่ยน และคำตอบเก็บแยกจากตัวหน้า (ใน Firebase หรือในเบราว์เซอร์)

## การใช้หน้าร่วมกันโดยไม่มีฐานข้อมูล (ไม่มี firebase.config.json)

- **ใส่ชื่อ:** แต่ละคนใส่ “ชื่อของคุณ” ที่หัวหน้า ชื่อจะแสดงข้างคำตอบเป็น “แก้ล่าสุด โดย …”
- **ส่งออก:** กด **ส่งออกไฟล์** จะได้ไฟล์ `requirement-answers-….json` ส่งให้ทีมทางช่องทางภายในเท่านั้น
- **นำเข้า:** กด **นำเข้าไฟล์** เพื่อรวมคำตอบ เลือกได้หลายไฟล์พร้อมกัน
  - ข้อที่ชนกันจะใช้ข้อที่แก้ล่าสุด ส่วนข้อใหม่จะถูกเพิ่มเข้าไป
  - กด **เลิกทำ** ได้ทันทีหลังนำเข้า
- **คำตอบเดิมจาก claude.ai:** นำเข้า `exports/claude-ai-20261118.json` ครั้งเดียว แล้วส่งไฟล์นี้ให้ทีมทางช่องทางภายใน
- **ล้างเบราว์เซอร์แล้วคำตอบหาย:** ควรส่งออกไฟล์เก็บไว้เป็นระยะ
- **ลืมรหัสที่จำไว้ในเครื่อง:** เปิดลิงก์ต่อท้ายด้วย `?forget`

## ข้อควรรู้ด้านความปลอดภัย

- **ความปลอดภัยขึ้นกับรหัสผ่าน:** ไฟล์ที่เข้ารหัสแล้วเปิดสาธารณะ ถ้ารหัสสั้นหรือเดาง่ายจะถูกเดาได้แบบ offline
- **ใครมีรหัสก็อ่านคำถามได้ทั้งหมด:** ถ้าต้องการเลิกให้สิทธิ์ใคร ให้ build ด้วยรหัสใหม่แล้ว push
- **ห้ามจดข้อมูลส่วนบุคคลของลูกค้า** (ชื่อ เบอร์โทร ที่อยู่) ลงในคำตอบ เพราะไฟล์ที่ส่งออกจะถูกส่งต่อกันในทีม
- **ถ้าใช้ Firebase:** คำตอบจะอยู่บน Google Cloud ตาม location ที่เลือก ตรวจนโยบายข้อมูลของบริษัทและของลูกค้าก่อนใช้ และสิทธิ์อ่านเขียนขึ้นกับรายชื่อใน `firestore.rules` เท่านั้น ห้ามตั้งเป็น `allow read, write: if true`
- **`src/index.src.html` เป็นฉบับทีม:** มีโน้ตที่ใช้ภายในทีม เปิดเองในเครื่องหรือใช้บน claude.ai ได้ แต่อย่าอัปโหลดขึ้นที่สาธารณะ
